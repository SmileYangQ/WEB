名詞小辭典(看不懂的字先查這裡)

名詞 白話解釋
Cloudflare 一家網路服務公司。我們用它的免費服務放網站和資料。
Worker Cloudflare 上跑你這個網站程式的地方。可以想成「一個放在網路上、24 小時開著的小店」。
worker.js 那個小店的全部程式,一個檔案。網頁、登入檢查、資料存取都在裡面。
D1 Cloudflare 的資料庫,用來存你的行程內容。可以想成「小店後面的倉庫」。
Binding(綁定) 把倉庫(D1)和小店(Worker)接上線的動作。沒綁,小店找不到倉庫。
Deploy(部署) 「把你剛改的東西正式上線」的按鈕。改了程式或變數,不按 Deploy,就沒有生效。
Variable / 變數 放在 Worker 設定裡的一個「名稱 + 值」,例如名稱 ALLOWED、值是一串 Gmail。
Text 與 Secret 變數的兩種類型。Text 設定後還看得到值;Secret 設定後再也看不到(只能覆蓋重填),用來放密鑰。
OAuth / Google 登入 讓網站借用 Google 的登入畫面,網站本身不用保管你的密碼。
OAuth 用戶端 你在 Google 那邊替「這個網站」申請的一張登記證,證上有「用戶端 ID」和「用戶端密鑰」。
用戶端 ID 登記證的編號,不算機密。
用戶端密鑰 登記證的暗號,是機密,不要貼給任何人。
重新導向 URI 登入完成後,Google 要把你送回哪個網址。必須和你的網站網址完全一樣,差一個字就會失敗。
測試使用者 Google 那邊的名單:App 還在「測試中」時,只有名單上的人能登入。
子網域 / <你的代號> 網址 africa-trip.<你的代號>.workers.dev 中間那一段。是你 Cloudflare 帳號的代號,預設用 email 前綴。
Console(控制台) D1 後台的一個輸入框,可以輸入指令查詢或修改資料。改的是正式資料,不能復原。
SQL 對資料庫下指令的語言。這份文件裡的 SQL 都是我寫好的,複製貼上就好。
種子資料 預先包在 worker.js 裡的那份行程資料。第一次登入時自動匯入 D1,之後就沒用了。
無痕視窗 瀏覽器的「不留紀錄」視窗,測試登入時用它,可以避免舊的登入狀態干擾。
Cookie / 登入狀態 瀏覽器記住「你已經登入」的小紀錄,在這個網站可維持 30 天。

0. 先搞懂:這套東西由哪三塊組成

用「房子與家具」來比喻

  • worker.js(程式碼) = 房子的結構與裝潢:牆壁在哪裡、有幾個房間、抽屜怎麼開。也就是「網頁長什麼樣子、有哪些功能、怎麼登入」。
  • D1(資料庫) = 搬進去住之後買的家具與雜物:你的行程細節、花費金額、待辦事項、行李清單。也就是「網站裡填的內容」。

兩者是分開處理的:

  • 想改裝潢(新功能、新版面)→ 換 worker.js,家具原封不動。
  • 想換家具(改內容)→ 直接在網頁上改,改的是 D1,房子不用動。

那 D1 裡的資料是誰放進去的?(很多人會疑惑)

你沒有手動放過任何東西。 流程是這樣:

  1. 步驟 1 你建的 D1 是一個空的資料庫(沒有表格、沒有資料)。
  2. 打包 worker.js 時,我先把你在 Claude 行程表資料庫裡當時的所有資料抄下來,一起包進 worker.js,這份叫「種子資料」。(你的檔案是 2026-10-28 抓的:22 段行程、17 個團行程日、17 個地點、9 項預算、16 個待辦、94 項行李、1 筆設定,共 176 筆。)
  3. 第一次成功登入網頁的那一刻,Worker 發現資料庫是空的,就自動:建好兩張表(docs、meta)→ 把種子資料一筆一筆放進 D1 → 在 meta 記一個「已匯入」標記。
  4. 之後再也不會匯入第二次。之後你在網頁上改的內容只存在 D1,worker.js 裡那份種子資料就沒用了。

所以:

  • 你在 Claude 那邊的行程表,在 10-28 之後改的內容,不會自動出現在 Cloudflare。兩邊是兩份獨立的資料。
  • 換新的 worker.js 不會覆蓋 D1 裡的資料(因為有「已匯入」標記)。

哪些變更要動哪一塊

你想做的事 動哪裡 資料會不會變
在網頁上改行程、備註、預算、待辦、行李 什麼都不用動 存進 D1
網頁功能或外觀大改(新分頁、新欄位) 換新的 worker.js 不會被洗掉
新增放資料的「集合」種類 換新的 worker.js 不會被洗掉
放行的人、Google 設定、密鑰 改 Worker 的 Variables,再 Deploy 不變
資料和網頁都大改,要整個重來 換 worker.js + 清空 D1 舊資料全部被取代(見 4-C)
在 Claude 增加了資料,想補到 Cloudflare 往 D1 補資料(見 4-D) 補進去

怎麼產生 SESSION_SECRET(隨機字串)

它是用來「簽名登入狀態」的暗號,要夠長夠亂,不要用生日或常見的字。任選一種方法:

方法 A:用瀏覽器產生(不需要裝任何東西)

  1. 用 Chrome 打開任一個 https:// 開頭的網頁(例如 https://www.google.com)。
  2. 按 F12(Mac 是 Cmd+Option+J),點上方的 Console(主控台)。
  3. 輸入(用打的比較不會被擋): crypto.randomUUID() + crypto.randomUUID() 按 Enter。

    Chrome 若提示「不要貼上不明程式碼」,是因為貼上的保護;用手打就不會被擋。

  4. 它會印出一長串像 '3f2b...-...-...' 的字,去掉前後的引號,整串複製起來,這就是 SESSION_SECRET(約 72 個字元,夠長了)。

方法 B:用密碼管理員 用你常用的密碼管理員(例如 Google 密碼管理工具、1Password)的「產生密碼」功能,長度選 32 以上,含英數字。

這串字只有你知道,不要貼給任何人(包括 Claude),也不要截圖。

做的過程中會產生好幾個要抄下來的東西,先列出來:

要記下的東西 在哪一步取得 機密嗎 你的紀錄
Cloudflare 帳號 email 註冊時 否
網址代號 <你的代號> 步驟 2 否
Worker 網址(https://africa-trip.<代號>.workers.dev) 步驟 2 否(但只給要用的人)
用戶端 ID 步驟 5 否
用戶端密鑰 步驟 5 是,機密 (存在密碼管理員,不要寫在這裡)

    • 按右上角的 Deploy。

    貼完請確認編輯器裡只有 worker.js 的內容,沒有殘留舊的範例程式,也不是只貼到一半。檔案很大(約 140KB),貼上要等幾秒,卡一下是正常的。

    1. Cloudflare 後台 → Workers & Pages 總覽頁 → 找 Account details 區塊 → Subdomain(或 workers.dev subdomain)旁的 Edit / Change(畫面名稱依記憶寫的,以你的畫面為準)。
    2. 改成想要的名稱:全站唯一,被用掉就換一個;建議不要用真名或 email。儲存(Cloudflare 可能警告舊網址會失效,此時還沒有人用,可放心)。
    3. 改完後,Worker 概覽頁顯示的網址就是新的了。

    它會影響這個帳號下所有 Worker。如果已經做到後面才想改,見 進階二,要多做一步:更新 Google 的重新導向 URI。

  6. 記下網址:https://africa-trip.<新代號>.workers.dev(Worker 概覽頁可看到)。下面稱它為「Worker 網址」,後面所有 <你的代號> 都請換成你現在的代號。填進 記事表。

步驟 4:不要開通 Zero Trust / Access(重要的轉折)

最初我們打算用 Cloudflare Access 做登入。實際操作時遇到:

問題 3:Worker 的 Access 分頁只出現「Set up Zero Trust for this account」✅ 畫面已對過。按下去之後,進入付款頁:Zero Trust Free、今天應付 $0、但要求輸入信用卡 / PayPal / Apple Pay / Google Pay ✅ 畫面已對過。

結論:Access 即使是免費方案,也要先留付款方式。你不想留,所以改用 Google 登入。

  • 你不需要開通 Zero Trust,Worker 的 Access 分頁不用理它,這一步跳過。
  • 如果你已經進到付款頁,直接按左上角 Back 離開即可。

回到目錄

步驟 5:在 Google 建立登入用的 OAuth 用戶端

這一步要換到 Google Cloud 網站。目的是向 Google 登記「我有一個網站,想讓人用 Google 帳號登入」,Google 會給你一組「用戶端 ID」和「用戶端密鑰」。

5-1 進入 Google Cloud 並建立專案

  1. 打開 https://console.cloud.google.com/ ,用 Google 帳號登入,同意條款。
  2. 上方專案選單 → 新增專案,名稱 africa-trip,建立後切換到這個專案(上方專案名稱會顯示 africa-trip)✅ 畫面已對過。

5-2 找到「OAuth 同意畫面」(Google Auth Platform)

問題 4:找不到「APIs & Services → OAuth consent screen」。 原因:你的 Google Cloud 是中文介面,選單名稱是中文;而且新版已改名為 Google Auth Platform。

三種找法,擇一:

  • 用最上方搜尋列輸入 Google Auth Platform(或 OAuth 同意畫面)。
  • 左上角 ≡ 選單 →「API 和服務」→「OAuth 同意畫面」(或直接點 Google Auth Platform)。
  • 網址列輸入 https://console.cloud.google.com/auth/overview(依記憶寫的,打不開就用前兩種)。

5-3 完成 OAuth 設定

  1. 若畫面中間有 開始使用(Get started),按它並填寫:
    • 應用程式名稱:行程表。
    • 使用者支援電子郵件:選你自己的 email。
    • 目標對象(Audience):選 外部(External)。
    • 聯絡資訊:填你的 email。同意條款,按 建立。
  2. 完成後畫面會跳出「OAuth 設定建立完成!」,並顯示「OAuth 總覽」,指標區寫著「尚未針對這項專案設定 OAuth 用戶端」✅ 畫面已對過。

5-4 建立 OAuth 用戶端

  1. 按 建立 OAuth 用戶端(或左側選單 用戶端 → 建立用戶端)。
  2. 應用程式類型選 網頁應用程式(Web application),名稱 行程表。
  3. 已授權的重新導向 URI → 新增 URI,貼上: https://africa-trip.<你的代號>.workers.dev/auth/callback
    • 前面一定要與 Worker 網址完全一致(把 <你的代號> 換成你真正的代號),後面接 /auth/callback,不要有空格、不要有結尾斜線。
    • 這是最常出錯的地方,貼完請放大檢查一次。
  4. 按 建立。完成後用戶端列表會出現「行程表」,類型「網頁應用程式」✅ 畫面已對過。
  5. 視窗會顯示 用戶端 ID 和 用戶端密鑰,兩個都複製存好(存到密碼管理員)。密鑰關掉視窗後可能看不到;忘了複製就進入「行程表」用戶端頁,新增一組新的密鑰即可。
    • 用戶端密鑰是機密,不要貼給任何人(包括 Claude)。

5-5 加入測試使用者

問題 5:找不到「加測試使用者」。 原因:它不在「用戶端」頁,而是在左側選單的 目標對象(Audience)頁。

  1. 左側選單點 目標對象:點 Google Auth Platform 標題旁盾牌圖示的小箭頭(▾)或左上角 ≡ 可打開選單。直接網址 https://console.cloud.google.com/auth/audience 是依記憶寫的,未確認。
  2. 發佈狀態請維持 測試中(Testing),不要按發佈。
  3. 測試使用者 區塊按 新增使用者(Add users),輸入要放行的 Gmail,每行一個,一定要包含你自己,儲存。
  4. 測試中的 App 登入時,Google 可能出現「尚未驗證這個應用程式」的警告 → 點 進階 → 繼續前往。因為只有你們自己用,不需要送 Google 審核。

✔ 完成標誌:你手上有「用戶端 ID」和「用戶端密鑰」(已存好),且「目標對象」頁的測試使用者名單裡有你自己的 Gmail,發佈狀態是「測試中」。

回到目錄

步驟 6:在 Worker 設定變數並 Deploy

回到 Cloudflare。Worker → Settings → Variables and Secrets → Add。依序新增(每次新增或修改後都要 Deploy):

名稱(全大寫,不可改) 類型 值
GOOGLE_CLIENT_ID Text 步驟 5-4 的用戶端 ID
GOOGLE_CLIENT_SECRET Secret 步驟 5-4 的用戶端密鑰
SESSION_SECRET Secret 你產生的隨機字串(見 準備)
ALLOWED Text 放行的 Gmail,用逗號隔開,例如 你的@gmail.com, 旅伴@gmail.com(一定要包含你自己)
VIEWERS Text(選用) 「只能看、不能改」的人的 Gmail。要先在 ALLOWED 內,再列在這裡

ALLOWED 的格式:多個 Gmail 之間可用逗號、分號、空白或換行隔開;大小寫不拘;不要有多餘的引號或錯字。

新手常犯的錯:

  • 變數名稱打錯(例如 GOOGLE_CLIENTID、小寫、多一個空格)。名稱必須和表格一模一樣。
  • 把密鑰類選成 Text,或把一般文字選成 Secret。照上表選就對了。
  • 設定完忘了按 Deploy。
  • 貼上的值前後多了空格或引號。

✔ 完成標誌:用瀏覽器打開 Worker 網址,看到「行程表登入」畫面和 使用 Google 登入 按鈕。

回到目錄

步驟 7:測試

  1. 用無痕視窗打開 Worker 網址 → 看到「行程表登入」與 使用 Google 登入 按鈕。
  2. 登入名單內的 Gmail → 進入行程表,資料已自動匯入(原理見 第 0 章)。
  3. 改一格內容、離開輸入框,右上角出現「已儲存」。
  4. 另一個名單內的帳號(或另一個瀏覽器)登入,約 6 秒內會看到你的修改。
  5. 用不在名單的 Google 帳號登入,應顯示「這個 Google 帳號不在允許名單內」。
  6. 設為唯讀的帳號(VIEWERS)登入後,右上角顯示「唯讀」,不能修改。
  7. (選做)確認資料真的進了 D1:Cloudflare → Storage & Databases → D1 SQL Database → africa-itinerary → Console,執行(只讀,不會改任何東西):
    SELECT coll, COUNT(*) FROM docs GROUP BY coll;
    預期:legs 22、days 17、places 17、bud 9、todo 16、pack 94、settings 1(共 176 筆)。後台分頁名稱依記憶寫的,找不到就截圖問 Claude。

✔ 完成標誌:第 1~3 點成功就是建置完成了。其他是進階檢查。

3. 日常管理

  • 登出:在 Worker 網址後加 /logout。登入一次可維持 30 天。在公用電腦用完請務必登出。
  • 讓所有人立刻登出:更換 SESSION_SECRET 的值,Deploy。
  • 備份:網頁右上角可匯出 Excel / CSV,定期匯出一份。換程式或清資料庫之前一定先匯出。
  • 資料以 Cloudflare 這邊為準;原本在 Claude 的行程表不會自動同步(原因見 第 0 章)。

怎麼邀請新成員(兩個地方都要加)

要讓一個新的人加入,兩個地方都要加他的 Gmail,缺一個都進不來:

  1. Google 的測試使用者:Google Cloud → Google Auth Platform → 目標對象 → 測試使用者 → 新增使用者。
  2. Cloudflare 的 ALLOWED:Worker → Settings → Variables and Secrets → ALLOWED → 在後面加上 , 他的@gmail.com → Deploy。
    • 只能看不能改的人,還要把他的 Gmail 加進 VIEWERS。

加完後傳給他:

  1. Worker 網址(用手機或電腦的 Chrome / Safari 打開,不要在 LINE 裡直接點,見 第 6 章)。
  2. 告訴他:「按『使用 Google 登入』,選你的 Gmail。如果看到『尚未驗證這個應用程式』,點進階 → 繼續前往。」

怎麼移除人

把他的 Gmail 從 ALLOWED(和 VIEWERS)刪掉 → Deploy。立刻失效,他已登入的狀態也會斷。順手也從 Google 的測試使用者名單移除。

4. 之後網頁或資料變了,要怎麼更新

先記住比喻:房子(worker.js)和家具(D1)分開處理。 先判斷你變動的是哪一塊(對照表在 第 0 章)。

4-A 只是在網頁上改內容(最常見)

直接在網頁上改,離開輸入框就存進 D1。不用動 worker.js,也不用動資料庫。 (別去改 worker.js 裡的資料,那份種子資料第一次匯入後已經沒用了,改了不會有任何效果。)

4-B 網頁(功能、外觀)有變,資料不動

要換新的 worker.js,資料庫原封不動。

  1. 在 Claude 對話跟 Claude 說要改什麼。網頁畫面是壓縮後包在 worker.js 裡的,不是人能手改的,請 Claude 重新打包一份。
  2. 先在網頁右上角匯出 Excel 備份,並把舊的 worker.js 存起來(新版有問題時可貼回去還原)。
  3. Cloudflare → Workers & Pages → 你的 Worker → Edit code → 全選刪除 → 貼上新的 worker.js → Deploy(貼法同 步驟 2 第 4 點)。
  4. 開網址、重新整理(必要時 Ctrl+F5),確認新功能出現、舊資料都還在。

資料不會被洗掉:因為 meta 裡已經有「已匯入」標記,新程式不會再匯入種子資料。

4-C 網頁和資料都大改,要整個重來(舊資料全部作廢)

這會刪掉 D1 裡目前所有內容,包括大家在網頁上改過的東西。做之前:

  1. 先匯出 Excel 備份,並通知其他人暫停編輯。
  2. 請 Claude 產生新的 worker.js(網頁新版 + 新的種子資料)。Claude 會從你在 Claude 裡的行程表資料庫取得最新資料,所以要重來的資料請先整理好在 Claude 那邊。
  3. 到 D1 的 Console,執行下面兩行,清空資料(兩行都要):
    DELETE FROM docs;
DELETE FROM meta;
  4. 立刻到 Worker → Edit code,貼上新的 worker.js → Deploy。
  5. 用被放行的帳號打開網址登入 → 程式發現資料庫是空的,自動匯入新的種子資料。
  6. 回 D1 Console 執行下面這行,確認筆數和你預期的一樣:
    SELECT coll, COUNT(*) FROM docs GROUP BY coll;

順序很重要:先清空(第 3 步),再換程式(第 4 步)。 原因:正在運作的舊版程式在記憶體裡記得「已經建好資料庫」,清空後它不會自己重新匯入,畫面會空白;要靠 Deploy 新版本,新版本才會重新檢查並匯入。所以第 3、4 步請連續做完,中間不要讓人編輯。 如果你是先換程式、後清空:換程式之後,新版會看到資料還在,不會匯入新資料;清空之後,畫面也會空白直到下次 Deploy。結果一樣麻煩,所以請照上面的順序。

(只換網頁、不想動資料,看 4-B;只想補一些資料進去,看 4-D。)

4-D 網頁沒變,但我在 Claude 那邊新增了資料,想補到 Cloudflare

資料庫不會自動同步,補進去有兩種做法:

做法 1:手動在 Cloudflare 的網頁重新輸入(資料少、最簡單) 新增的列不多就直接用 Cloudflare 的網頁加上去,不會有任何風險。

做法 2:請 Claude 幫你產生「補資料的 SQL」,你貼到 D1 Console 執行(資料多)

  1. 跟 Claude 說:「我在 Claude 的行程表新增了資料,請幫我產生補進 Cloudflare 的 SQL。」
  2. Claude 會拿目前 Claude 資料庫的內容,和 2026-10-28 抓的那份種子資料比對,找出新增、修改、刪除的列,產生 SQL 給你。
  3. 先匯出 Excel 備份。到 D1 Console 貼上執行(後台 Console 對單次貼上的長度可能有限制,太長 Claude 會拆成幾段)。
  4. 重新整理 Cloudflare 的網頁,確認資料出現。

兩個注意點:

  • 預設只補「新增的列」(用「已經有就跳過」的寫法),不會蓋掉大家在 Cloudflare 上已經改過的內容。要連「修改過的列」一起覆蓋,要告訴 Claude,並先確認 Cloudflare 那邊沒有人改過同一列,否則 Cloudflare 的修改會被蓋掉。
  • Claude 看不到 Cloudflare 資料庫裡現在是什麼,所以它只能比對「Claude 這邊的變動」。如果兩邊都改過同一列,請你告訴 Claude 要以哪邊為準。

5. 進階

進階一:更換 Google 用戶端 ID(或密鑰)

問題 6:想把用戶端 ID 換掉。 說明:用戶端 ID 是 Google 自動產生的,不能自己指定或修改;在用戶端頁面只能改「顯示名稱」。想換 ID,只能建一個新的用戶端,再換掉舊的。

  1. Google Auth Platform → 用戶端 → 建立 OAuth 用戶端,類型選 網頁應用程式。
  2. 重新導向 URI 填一樣的:https://africa-trip.<你的代號>.workers.dev/auth/callback。
  3. 建立後取得新的用戶端 ID 和用戶端密鑰,兩個都存好。
  4. Cloudflare Worker → Settings → Variables and Secrets,把 GOOGLE_CLIENT_ID 與 GOOGLE_CLIENT_SECRET 兩個一起換成新的值(新舊不能混用),按 Deploy。
  5. 用無痕視窗登入測試,確認新的可以用。
  6. 確認沒問題後,回 Google 把舊的用戶端刪除,舊 ID 與密鑰就完全失效。

只是擔心密鑰外洩:不用換 ID,在同一個用戶端新增一組密鑰 → 更新 GOOGLE_CLIENT_SECRET → 刪掉舊密鑰即可。

用戶端 ID 本身不算機密(它會出現在登入時的網址裡);要保密的是用戶端密鑰和 SESSION_SECRET。

進階二:把網址中的 <你的代號> 改掉(workers.dev 子網域)

問題 7:網址 https://africa-trip.<你的代號>.workers.dev 裡的「代號」預設用了我的 email 前綴,不想讓它出現在網址裡。 說明:這個代號是 Cloudflare 帳號層級的 workers.dev 子網域,可以改,但會影響這個帳號下所有 Worker。最好在步驟 2 就先改(見 步驟 2 第 5 點);已經做到後面才改的話,看這裡。

改子網域

(畫面名稱是依記憶寫的,以你的畫面為準)

  1. Cloudflare 後台 → Workers & Pages 總覽頁。
  2. 找 Account details 區塊,裡面有 Subdomain(或 workers.dev subdomain),旁邊有 Edit / Change。
  3. 改成想要的名稱。必須在 Cloudflare 全站唯一,被用掉就換一個;建議不要用真名或 email。
  4. 儲存。Cloudflare 可能會警告舊網址將失效。

改完一定要做的事

  1. 新網址:https://africa-trip.<新名稱>.workers.dev。
  2. Google 用戶端 → 點「行程表」→ 把已授權的重新導向 URI 改成 https://africa-trip.<新名稱>.workers.dev/auth/callback(舊的可刪)。 沒做這步,登入會出現 redirect_uri_mismatch。
  3. 用無痕視窗打開新網址,測試登入。
  4. 把新網址告訴要使用的人。

改動的影響

  • 舊網址立刻失效。
  • 所有人要重新登入一次(登入狀態綁在網址上)。
  • ALLOWED、SESSION_SECRET、資料庫都不用動,資料不會消失。

其他選擇

  • 自訂網址(例如 trip.你的網域.com):要買網域,一年約 US$10 起,再綁到 Worker。不想花錢就用上面改子網域的做法。
  • Worker 名稱 africa-trip 也想換:我不確定能不能直接改名,通常是新建一個 Worker、貼上程式、重新綁 D1 與設定變數。只想把 email 從網址拿掉的話,改子網域就夠,不用動 Worker 名稱。

6. 額度與使用提醒

免費額度夠不夠用?

  • 你的 Workers 總覽頁顯示「Requests today 0 / 100,000」✅ 畫面已對過,也就是免費版每天約 10 萬次請求。
  • 這個網站每次開頁面、每次存檔、以及網頁開著且在前景時每 6 秒的「有沒有新資料」檢查,都算請求。
  • 粗估(我的估算,不是實測):一個分頁開著且停在前景,1 小時約 600 次。5 個人各開 8 小時,約 2 萬多次,遠低於 10 萬。背景分頁不會檢查,所以放著不看不會一直消耗。
  • 如果有一天超過額度,Worker 會暫時無法使用,隔天重置(這是我印象中的行為,以 Cloudflare 說明為準)。真的遇到,請 Claude 把檢查間隔拉長。
  • D1 資料庫也有免費額度(我記得每天可讀數百萬列),這個用量遠遠用不到。要看實際用量,到後台的 Metrics 頁。

用手機或 LINE 開的時候

  • 手機可以用,版面會自動變成手機版。
  • 不要在 LINE、Facebook、Instagram 的內建瀏覽器裡直接登入。Google 通常不允許在 App 內建瀏覽器完成登入,會顯示「不符合 Google 的安全瀏覽器政策」之類的錯誤(這是我對 Google 政策的印象,沒有在你的環境實測)。
  • 解法:在 LINE 點網址後,按右上角「…」→ 用其他瀏覽器開啟(或「用 Chrome / Safari 開啟」),再登入。
  • 手機登入後也可以把網站「加到主畫面」,以後像 App 一樣點開。

其他使用提醒

  • 改完一格要離開輸入框(點別處),右上角看到「已儲存」才算存好。
  • 兩個人同時改同一格,後存的會蓋掉先存的;約 6 秒後大家的畫面會同步成最新版。
  • 資料會一直累積在 D1,沒有自動備份,要定期匯出 Excel。

「這個 Google 帳號不在允許名單內」的檢查清單

出現這個訊息,代表 Google 登入與 Worker 都已正常運作,只是名單比對不通過。逐項檢查:

  1. 改了 ALLOWED 之後有沒有按 Deploy(沒 Deploy 變數不會生效)。
  2. 名單裡的 Gmail 是不是這個 Google 帳號登入時用的完整地址(有些帳號用別的信箱註冊,或名單寫成別名)。
  3. 有沒有錯字、多餘引號,或變數名稱不是 ALLOWED。
  4. 想讓某人「只能看」:他的 Gmail 要同時在 ALLOWED 和 VIEWERS。

8. 安全說明

  • 沒登入或不在名單的人,Worker 在伺服器端就拒絕,拿不到網頁與資料。
  • 被放行的人在瀏覽器中仍看得到網頁程式碼(網頁的本質),已壓縮混淆,只擋得住隨手複製。
  • 被放行的人都能看到並修改全部資料(除非列入 VIEWERS)。
  • 護照號碼、訂位代號等敏感資料不要放進去。
  • 用戶端密鑰與 SESSION_SECRET 是機密:不要貼在聊天、文件或截圖中。若不慎外洩,在 Google 用戶端頁重新產生密鑰、並更換 SESSION_SECRET。
  • 與 Cloudflare Access 相比,少了企業級管理功能(裝置檢查、登入紀錄),個人旅遊用途足夠。
  • D1 Console 執行的是正式資料庫,不能復原;DELETE 之類的指令執行前務必先匯出備份。
